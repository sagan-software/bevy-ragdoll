# Phase 14: 2D ragdolls

Goal: 2D profiles and runtime in the core behind feature `2d`, and the
`bevy_ragdoll_rapier2d` and `bevy_ragdoll_avian2d` backends.

Read first: [../architecture.md](../architecture.md); the 3D modules you
are mirroring; bevy_rapier2d 0.36 and avian2d 0.7 sources (cached under
`~/.cargo/registry/src/*/avian2d-0.7.0`; download bevy_rapier2d's crate
tarball to read it).

## Design

- 2D lives in `bevy_ragdoll::d2` with its own types: `ProfileSpec2d`
  (bodies with `Capsule2d`, `Circle`, `Rectangle` shapes in the body frame,
  `rest: Isometry2d`), joints with one `AngleRange` and `max_torque`.
  Validation, derived masks, budget, hits, blend and the backend contract
  have the same shape and names with a `2d` suffix where types differ.
  Share dimension-free code (budget, hit falloff over the body tree,
  drive scalar maths) instead of duplicating it.
- Bevy has no 2D skinning. A 2D ragdoll drives a `Transform` hierarchy
  (one sprite per limb). Capture and writeback work as in 3D on the
  hierarchy's bones.
- Joint angle is the relative angle; muscle drive uses the revolute motor
  on both engines (both have native 2D revolute motors).

## Steps

1. Failing tests first: profile validation for 2D, runtime binding and
   writeback on a sprite hierarchy, and the contract and physics tiers in
   `bevy_ragdoll_conformance::d2` (drop and settle, impulse momentum,
   motor holds pose, limits respected).
2. Implement `d2` in the core, then each backend following its 3D twin.
3. Examples `stick_figure_2d`, `chain_2d`, `creature_2d` with simple CC0
   sprites drawn in code (shapes) so no new assets are needed.
4. Stress example gains `--dimension 2d` with `pile` and `grid`.

## Done when

- Both 2D backends pass both tiers.
- Screenshots of the three examples; defects listed.
- Sweep includes 2D rows; baseline committed.
- `PLAN.md` marks phase 14 done.
